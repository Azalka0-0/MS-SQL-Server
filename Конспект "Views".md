## 1. Представления (Views)

**Представление (View)** — это виртуальная таблица.

В отличие от обычной таблицы, представление содержит запрос, который динамически извлекает используемые данные.

Представление состоит из:

- именованных столбцов;
- строк данных.

Пока представление не будет проиндексировано, оно не существует в базе данных как хранимая совокупность значений. Строки и столбцы извлекаются из таблиц, указанных в определяющем представление запросе, и динамически формируются при обращении к представлению.

Представление выполняет функцию фильтра базовых таблиц, на которые оно ссылается.

Определяющий запрос представления может обращаться:

- к одной таблице;
- к нескольким таблицам;
- к другим представлениям;
- к таблицам или представлениям текущей базы данных;
- к объектам других баз данных.

Также можно использовать распределённые запросы для представлений, работающих с несколькими разнородными источниками.

Например, можно объединить структурированные подобным образом данные, которые находятся на разных серверах и относятся к разным отделам организации.

---

# 2. Преимущества представлений

Представления дают несколько преимуществ.

### Упрощение SQL-операций

Сложные SQL-запросы можно сохранить в представлении и обращаться к ним как к виртуальной таблице.

### Защита данных

Представление может предоставлять доступ только к определённой части таблицы, а не ко всей таблице.

Таким образом, пользователю можно разрешить работу с представлением, не предоставляя ему непосредственный доступ к базовой таблице.

### Удобное представление данных

Представления позволяют возвращать отформатированные значения из таблиц в нужной и удобной форме.

### Настройка восприятия данных

Представления позволяют формировать удобный интерфейс для разных пользователей.

### Механизм безопасности

Пользователи могут обращаться к данным через представления, не имея разрешений на непосредственный доступ к базовым таблицам.

### Обратная совместимость

Представление может моделировать таблицу, которая существует, но структура которой была изменена.

### Копирование и секционирование

Представления могут использоваться при прямом и обратном копировании данных в SQL Server для повышения производительности и секционирования данных.

---

# 3. Типы представлений

В SQL Server выделяются следующие типы представлений:

1. **Определяемые пользователем представления**
2. **Индексированные представления**
3. **Секционированные представления**
4. **Системные представления**

---

# 4. Индексированные представления

**Индексированное представление** — это материализованное представление.

В отличие от обычного представления, определение вычисляется, а результирующие данные хранятся так же, как данные таблицы.

Индексировать представление можно, создав для него **уникальный кластеризованный индекс**.

Индексированные представления могут существенно повысить производительность некоторых типов запросов.

Особенно эффективно их использовать в запросах, которые группируют большое количество строк.

При этом индексированные представления не очень хорошо подходят для часто обновляющихся базовых наборов данных.

---

# 5. Секционированные представления

**Секционированное представление** — это представление, соединяющее горизонтально секционированные данные набора таблиц-элементов.

Эти таблицы могут находиться:

- на одном сервере;
- на нескольких серверах.

Для пользователя данные выглядят так, будто находятся в одной таблице.

Если представление соединяет таблицы-элементы одного экземпляра SQL Server, оно называется **локальным секционированным представлением**.

---

# 6. Системные представления

**Системные представления** предоставляют доступ к метаданным каталога.

Они позволяют получать сведения:

- об экземпляре SQL Server;
- о базах данных;
- об объектах, определённых в экземпляре;
- о других системных объектах.

Например:

```sql
SELECT *
FROM sys.databases;
```

`sys.databases` позволяет получить сведения о базах данных, доступных в экземпляре SQL Server.

---

# 7. Модифицируемое представление

**Модифицируемое представление** — представление, через которое можно изменять данные базовой таблицы.

Если представление является модифицируемым, операции:

```sql
UPDATE
INSERT
DELETE
```

над представлением приводят к изменению данных в таблице, на которой оно основано.

---

# 8. Немодифицируемые представления

Не все представления являются модифицируемыми.

Большая часть представлений является немодифицируемой.

Основная проблема возникает при неоднозначности.

Например, если представление содержит данные из двух таблиц и пользователь удаляет одну строку из представления, возникает вопрос:

- из какой таблицы удалять данные;
- удалять ли данные из обеих таблиц;
- какую именно исходную запись изменять.

Из-за такой неоднозначности представление может быть немодифицируемым.

---

# 9. Критерии модифицируемого представления

Для определения того, является ли представление модифицируемым, используются определённые критерии.

## Критерий 1

Представление должно выводиться **из одной и только одной базовой таблицы**.

```text
View
 ↓
одна базовая таблица
```

## Критерий 2

Представление должно содержать первичный ключ базовой таблицы.

В материалах отмечается, что технически это не является требованием стандарта ANSI, но придерживаться этого правила рекомендуется.

## Критерий 3

Представление не должно содержать поля, являющиеся результатом агрегатных функций.

Например:

```sql
SUM(...)
AVG(...)
COUNT(...)
```

## Критерий 4

В определении не должно быть:

```sql
DISTINCT
```

## Критерий 5

В определении не должны использоваться:

```sql
GROUP BY
HAVING
```

---

# 10. Дополнительные критерии

## Подзапросы

Представление не должно использовать подзапросы.

В презентации отмечается, что это ограничение относится к ANSI, а некоторые реализации могут иметь свои особенности.

## Использование другого представления

Представление может быть основано на другом представлении.

Но используемое представление также должно быть модифицируемым.

## Константы и выражения

Представление не должно использовать среди выбранных полей вывода:

- константы;
- строки;
- выражения значений.

Например:

```sql
comm * 100
```

## INSERT

Для `INSERT` представление должно содержать все поля основной таблицы, которые имеют ограничение:

```sql
NOT NULL
```

если для них не определено другое значение по умолчанию.

# 12. Таблица Products

```sql
CREATE TABLE Products
(
    Id INT IDENTITY PRIMARY KEY,
    ProductName NVARCHAR(30) NOT NULL,
    Manufacturer NVARCHAR(20) NOT NULL,
    ProductCount INT DEFAULT 0,
    Price MONEY NOT NULL
);
```

Таблица содержит:

| Поле | Тип | Назначение |
|---|---|---|
| `Id` | `INT IDENTITY PRIMARY KEY` | Идентификатор товара |
| `ProductName` | `NVARCHAR(30)` | Название товара |
| `Manufacturer` | `NVARCHAR(20)` | Производитель |
| `ProductCount` | `INT` | Количество товара |
| `Price` | `MONEY` | Цена |

---

# 13. Таблица Customers

```sql
CREATE TABLE Customers
(
    Id INT IDENTITY PRIMARY KEY,
    FirstName NVARCHAR(30) NOT NULL
);
```

Поля:

| Поле | Тип | Назначение |
|---|---|---|
| `Id` | `INT IDENTITY PRIMARY KEY` | Идентификатор клиента |
| `FirstName` | `NVARCHAR(30)` | Имя клиента |

---

# 14. Таблица Orders

```sql
CREATE TABLE Orders
(
    Id INT IDENTITY PRIMARY KEY,
    ProductId INT NOT NULL REFERENCES Products(Id) ON DELETE CASCADE,
    CustomerId INT NOT NULL REFERENCES Customers(Id) ON DELETE CASCADE,
    CreatedAt DATE NOT NULL,
    ProductCount INT DEFAULT 1,
    Price MONEY NOT NULL
);
```

Поля:

| Поле | Тип | Назначение |
|---|---|---|
| `Id` | `INT IDENTITY PRIMARY KEY` | Идентификатор заказа |
| `ProductId` | `INT NOT NULL` | Ссылка на товар |
| `CustomerId` | `INT NOT NULL` | Ссылка на клиента |
| `CreatedAt` | `DATE` | Дата создания заказа |
| `ProductCount` | `INT` | Количество товара |
| `Price` | `MONEY` | Цена |

`ProductId` связан с:

```sql
Products(Id)
```

`CustomerId` связан с:

```sql
Customers(Id)
```

Для обеих внешних связей используется:

```sql
ON DELETE CASCADE
```

# 15. Создание представления

Для создания представления используется команда:

```sql
CREATE VIEW
```

Общая форма:

```sql
CREATE VIEW название_представления
    [(столбец_1, столбец_2, ...)]
AS
    выражение_SELECT;
```

Пример:

```sql
CREATE VIEW OrdersProductsCustomers
AS
SELECT
    Orders.CreatedAt AS OrderDate,
    Customers.FirstName AS Customer,
    Products.ProductName AS Product
FROM Orders
INNER JOIN Products
    ON Orders.ProductId = Products.Id
INNER JOIN Customers
    ON Orders.CustomerId = Customers.Id;
```

---

# 16. Правила создания представлений

При создании представлений необходимо учитывать несколько ограничений.

### Уникальное имя

Представление, как и таблица, должно иметь уникальное имя в рамках той же базы данных.

### Количество столбцов

Представление может иметь не более:

```text
1024 столбцов
```

### Количество таблиц

Представление может обращаться не более чем к:

```text
256 таблицам
```

### Вложенные представления

Представления могут создаваться на основе других представлений.

Такие представления называются **вложенными (nested views)**.

Максимальный уровень вложенности:

```text
32
```

### Ограничения SELECT

Команда `SELECT`, используемая при создании представления, не может включать:

```sql
INTO
```

и

```sql
ORDER BY
```

за исключением случаев, когда также применяется:

```sql
TOP
```

или:

```sql
OFFSET
```

Если сортировка нужна при получении данных из представления, `ORDER BY` используется в запросе, который обращается к представлению.

# 17. Задание столбцов представления

При создании представления можно явно задать имена его столбцов.

Пример:

```sql
CREATE VIEW OrdersProductsCustomers2
    (OrderDate, Customer, Product)
AS
SELECT
    Orders.CreatedAt,
    Customers.FirstName,
    Products.ProductName
FROM Orders
INNER JOIN Products
    ON Orders.ProductId = Products.Id
INNER JOIN Customers
    ON Orders.CustomerId = Customers.Id;
```

Здесь имена столбцов представления:

```text
OrderDate
Customer
Product
```

# 18. Представление из трёх таблиц

Создадим представление, объединяющее данные:

- о заказе;
- о клиенте;
- о товаре.

```sql
CREATE VIEW OrdersProductsCustomers
AS
SELECT
    Orders.CreatedAt AS OrderDate,
    Customers.FirstName AS Customer,
    Products.ProductName AS Product
FROM Orders
INNER JOIN Products
    ON Orders.ProductId = Products.Id
INNER JOIN Customers
    ON Orders.CustomerId = Customers.Id;
```

Фактически это представление возвращает сводные данные из трёх таблиц.

После создания представление можно увидеть в узле **Views** выбранной базы данных в SQL Server Management Studio.

---

# 19. Получение данных из представления

После создания представления к нему можно обращаться практически как к таблице.

Например:

```sql
SELECT *
FROM OrdersProductsCustomers;
```

При выполнении запроса представление получает данные из исходных таблиц согласно своему определяющему запросу.

# 20. Изменение представления

Для изменения представления используется:

```sql
ALTER VIEW
```

Синтаксис практически такой же, как у `CREATE VIEW`:

```sql
ALTER VIEW название_представления
    [(столбец_1, столбец_2, ...)]
AS
    выражение_SELECT;
```

---

# 21. Пример изменения представления

Допустим, в существующее представление необходимо добавить производителя товара.

```sql
ALTER VIEW OrdersProductsCustomers
AS
SELECT
    Orders.CreatedAt AS OrderDate,
    Customers.FirstName AS Customer,
    Products.ProductName AS Product,
    Products.Manufacturer AS Manufacturer
FROM Orders
INNER JOIN Products
    ON Orders.ProductId = Products.Id
INNER JOIN Customers
    ON Orders.CustomerId = Customers.Id;
```

Теперь представление возвращает дополнительный столбец:

```text
Manufacturer
```

---

# 22. Удаление представления

Для удаления представления используется:

```sql
DROP VIEW
```

Пример:

```sql
DROP VIEW OrdersProductsCustomers;
```

При удалении таблиц также следует учитывать представления, которые используют эти таблицы.

Если таблица является базой для представления, её удаление может повлиять на работу этого представления.

# 28. Основные понятия

| Понятие | Значение |
|---|---|
| `VIEW` | Виртуальная таблица |
| `CREATE VIEW` | Создание представления |
| `ALTER VIEW` | Изменение представления |
| `DROP VIEW` | Удаление представления |
| `sys.databases` | Системное представление со сведениями о БД |
| Indexed View | Материализованное представление с индексом |
| Partitioned View | Представление, объединяющее секционированные данные |
| System View | Представление для доступа к метаданным |
| Modifiable View | Представление, через которое можно изменять данные базовой таблицы |
| Nested View | Представление, созданное на основе другого представления |

# 29. Главное для запоминания

```text
VIEW = виртуальная таблица
```

Обычное представление не хранит собственный набор данных — оно динамически получает данные из таблиц, указанных в запросе.

```sql
CREATE VIEW
```

— создать представление.

```sql
ALTER VIEW
```

— изменить представление.

```sql
DROP VIEW
```

— удалить представление.

```sql
SELECT * FROM ViewName;
```

— получить данные из представления.

## Модифицируемое представление

Основная идея:

```text
одна базовая таблица
        ↓
   простое VIEW
        ↓
UPDATE / INSERT / DELETE
        ↓
изменение базовой таблицы
```

Чем больше в представлении сложных конструкций — `JOIN`, `GROUP BY`, `HAVING`, `DISTINCT`, агрегатов, подзапросов и выражений — тем выше вероятность, что оно будет немодифицируемым.

# Итог

**VIEW (представление)** — это виртуальная таблица, содержимое которой определяется SQL-запросом.

Представления позволяют:

- упрощать сложные SQL-запросы;
- ограничивать доступ к данным;
- предоставлять пользователям только нужные столбцы и строки;
- объединять данные из нескольких таблиц;
- создавать удобный интерфейс для работы с базой данных;
- использовать системные метаданные;
- в отдельных случаях материализовать результат с помощью индексированного представления.

Основные команды:

```sql
CREATE VIEW
ALTER VIEW
DROP VIEW
```

Основные типы:

```text
Индексированные
Секционированные
Системные
Пользовательские
```

А при работе с модифицируемыми представлениями необходимо проверять ограничения, связанные со структурой исходных данных и используемым SQL-запросом.
