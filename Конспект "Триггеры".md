------------------------------------------------------------------------

# Что такое триггер

**Триггер** --- это откомпилированная SQL-процедура, выполнение которой
обусловлено наступлением определённых событий внутри реляционной базы
данных.

Триггер автоматически запускается сервером при наступлении события, для
которого он создан, и не имеет параметров.

Основные особенности: - не вызывается явно, как обычная процедура; -
становится «одним целым» с вызвавшей операцией; - может содержать
несколько SQL-инструкций; - может использовать `IF`, `WHILE` и другие
конструкции T-SQL.

Триггеры появились в SQL Server 2005.

------------------------------------------------------------------------

# Назначение триггеров

Триггеры используются для: - проверки корректности данных; - сложных
ограничений целостности; - аудита и фиксации изменений; -
автоматического оповещения других модулей; - реализации бизнес-правил; -
каскадных воздействий; - поддержки репликации.

## Когда нужны триггеры

Триггер нужен, когда требуется: 1. Сравнить состояние таблицы до и после
изменения. 2. Предотвратить нарушение бизнес-логики. 3. Выполнить
каскадные изменения, которые нельзя реализовать обычными каскадными
ограничениями. 4. Предотвратить неправильные `INSERT`, `UPDATE`,
`DELETE`. 5. Реализовать ограничения, которые нельзя выразить через
`CHECK`. 6. Проверять данные с обращением к другим таблицам.

------------------------------------------------------------------------

# DML-триггеры

**DML-триггер** --- блок, автоматически выполняемый при событии
изменения данных.

События: - `INSERT` - `UPDATE` - `DELETE`

DML-триггер может быть определён для таблицы или `VIEW`. Для обычного
запроса триггер определить нельзя.

Триггер создаётся по одной таблице, но может обращаться к другим
таблицам и объектам других БД.

> Таблица, по которой определяется триггер, называется **таблицей
> триггера**.

------------------------------------------------------------------------

# Основные параметры триггера

  Параметр             Значение
  -------------------- ----------------------------------
  Имя                  Имя триггера
  Объект               Таблица или представление
  Время срабатывания   `AFTER` / `FOR` или `INSTEAD OF`
  Событие              `INSERT`, `UPDATE`, `DELETE`
  Тело                 SQL-код после `AS`

Один триггер может реагировать на несколько событий:

``` sql
INSERT, UPDATE
```

или:

``` sql
INSERT, UPDATE, DELETE
```

`TRUNCATE TABLE` не является событием `DELETE` для DML-триггера.

------------------------------------------------------------------------

# Правила работы триггеров

Триггер запускается после завершения оператора, который вызвал его
активизацию.

Если исходный оператор нарушает ограничение таблицы или вызывает другую
ошибку, связанный с ним триггер не активизируется.

## Триггер и транзакция

Триггер является частью одной транзакции вместе с вызвавшей его
операцией.

``` sql
ROLLBACK;
```

может отменить как исходную операцию, так и изменения, сделанные
триггером.

При ошибке в триггере происходит откат всей транзакции.

### Важный момент

Триггер активизируется **один раз для одного оператора**, даже если
оператор изменяет несколько строк.

------------------------------------------------------------------------

# Рекурсия и вложенность

SQL Server позволяет использовать вложенные триггеры до **32 уровней**.

## Косвенная рекурсия

``` text
UPDATE T1
  ↓
TR1
  ↓
UPDATE T2
  ↓
TR2
  ↓
UPDATE T1
```

## Прямая рекурсия

``` text
UPDATE T1
  ↓
TR1
  ↓
UPDATE T1
  ↓
TR1
  ↓
...
```

При бесконечном цикле запуск триггеров отменяется.

Если вложенный триггер выполняет `ROLLBACK`, последующие триггеры не
запускаются.

------------------------------------------------------------------------

# AFTER и INSTEAD OF

## INSTEAD OF

`INSTEAD OF` выполняется **вместо** исходного SQL-оператора и
переопределяет его действие.

Можно задать по одному `INSTEAD OF` на `INSERT`, `UPDATE` или `DELETE`.

Он может быть определён для таблицы и/или представления.

Пример:

``` sql
CREATE TRIGGER plus_1
ON table1
INSTEAD OF INSERT
AS
    INSERT table1 (id, col1)
    SELECT id + 1, col1
    FROM inserted;
```

`INSTEAD OF` используется для выборочного запрещения операции, проверки
предусловий и изменения поведения `INSERT`/`UPDATE`/`DELETE`.

------------------------------------------------------------------------

# AFTER

`AFTER` может быть определён только для таблиц.

Он активизируется после успешного выполнения всех операций исходного
SQL-оператора, включая проверки ограничений и каскадные действия.

Используется для: - учёта выполненных операций; - аудита; - проверки
постусловий; - действий после успешного изменения данных.

## Порядок AFTER-триггеров

Для нескольких `AFTER`-триггеров можно задать первый и последний:

``` sql
sp_settriggerorder
    @triggername = 'AnotherTrigger',
    @order = 'first';

sp_settriggerorder
    @triggername = 'MyTrigger',
    @order = 'last';
```

Если триггеров больше двух, порядок остальных определяется произвольно.

------------------------------------------------------------------------

# Таблицы inserted и deleted

При выполнении DML-триггера доступны две специальные временные
таблицы: - `inserted`; - `deleted`.

Они находятся в памяти и имеют ту же структуру, что и таблица триггера.

  Операция   `inserted`       `deleted`
  ---------- ---------------- ------------------
  `INSERT`   Новые строки     Пустая
  `DELETE`   Пустая           Удаляемые строки
  `UPDATE`   Новые значения   Старые значения

## UPDATE

`UPDATE` рассматривается как `DELETE` старых значений с последующим
`INSERT` новых.

Поэтому: - старые значения попадают в `deleted`; - новые значения
попадают в `inserted`.

Это позволяет сравнивать состояние строки до и после изменения.

------------------------------------------------------------------------

# Создание DML-триггера

Синтаксис:

``` sql
CREATE TRIGGER [schema_name.]trigger_name
ON { table | view }
{ FOR | AFTER | INSTEAD OF }
{ [ INSERT ] [ , ] [ UPDATE ] [ , ] [ DELETE ] }
AS
{ sql_statement }
```

Пример:

``` sql
CREATE TRIGGER trg
ON my_table
FOR INSERT, UPDATE, DELETE
AS
    SELECT 'this is trigger';
```

------------------------------------------------------------------------

# Обработка ошибок

Используются: - `ROLLBACK`; - `RAISERROR`; - `TRY...CATCH`.

``` sql
ROLLBACK;
```

отменяет транзакцию.

Пример `RAISERROR`:

``` sql
RAISERROR (
    'Error raised because of wrong data.',
    16,
    1
);
```

## Функции ошибок

  Функция               Назначение
  --------------------- ---------------------------------------------
  `ERROR_LINE()`        Номер строки ошибки
  `ERROR_MESSAGE()`     Текст ошибки
  `ERROR_NUMBER()`      Номер ошибки
  `ERROR_PROCEDURE()`   Процедура или триггер, где произошла ошибка
  `ERROR_SEVERITY()`    Уровень серьёзности
  `ERROR_STATE()`       Состояние

`ERROR_PROCEDURE()` возвращает `NULL`, если ошибка произошла не внутри
процедуры или триггера.

# Пример триггера с проверкой данных

Пример из презентации проверяет рейтинг поставщика:

``` sql
CREATE TRIGGER LowCredit
ON Purchasing.PurchaseOrderHeader
AFTER INSERT
AS
BEGIN
    DECLARE @creditrating tinyint,
            @vendorid int;

    SELECT
        @creditrating = v.CreditRating,
        @vendorid = p.VendorID
    FROM Purchasing.PurchaseOrderHeader p
    JOIN inserted i
        ON p.PurchaseOrderID = i.PurchaseOrderID
    JOIN Purchasing.Vendor v
        ON v.VendorID = i.VendorID;

    IF @creditrating = 5
        RAISERROR (
            'This vendor''s credit rating is too low to accept new purchase orders.',
            16,
            1
        );
END
```

Логика: после `INSERT` берётся добавленная запись из `inserted`,
определяется рейтинг поставщика, и при рейтинге `5` формируется ошибка.

------------------------------------------------------------------------

# Управление триггерами

## Изменение

``` sql
ALTER TRIGGER trigger_name
...
```

Пример:

``` sql
ALTER TRIGGER tr_name
ON on_board
AFTER UPDATE
AS
    UPDATE on_board
    SET iks = 'b'
    WHERE id IN (SELECT id FROM inserted);
```

## Удаление

``` sql
DROP TRIGGER tr_name;
```

## Отключение

``` sql
DISABLE TRIGGER trigger_name
ON object_name;
```

Все триггеры объекта:

``` sql
DISABLE TRIGGER ALL
ON object_name;
```

## Включение

``` sql
ENABLE TRIGGER trigger_name
ON object_name;
```

Все:

``` sql
ENABLE TRIGGER ALL
ON object_name;
```

# Применение триггеров

### Защита

Запрещение доступа или операций в зависимости от значений данных.

### Учёт

Ведение журналов изменений.

### Целостность

Сложные правила целостности и ссылочной целостности.

### Производные данные

Автоматическое вычисление значений.

# DDL-триггеры

DDL-триггеры реагируют на события языка определения данных:

-   `CREATE`;
-   `ALTER`;
-   `DROP`.

Они применяются для административных задач, аудита и регулирования
операций БД.

## Задачи

1.  Предотвращать определённые изменения схемы.
2.  Выполнять действия после изменения схемы.
3.  Записывать изменения и события схемы.

DDL-триггеры срабатывают после соответствующих DDL-инструкций и не
используют `INSTEAD OF`.

Они также не создают `inserted` и `deleted`.

## Синтаксис

``` sql
CREATE TRIGGER trigger_name
ON { DATABASE | ALL SERVER }
{ FOR | AFTER }
{ event_type | event_group }
AS
{ sql_statement [ ; ] [ ,...n ] [ ; ] }
```

## Пример

``` sql
CREATE TRIGGER ddl_trig_database
ON ALL SERVER
FOR CREATE_DATABASE
AS
    PRINT 'Database Created.';
```

Удаление:

``` sql
DROP TRIGGER ddl_trig_database
ON ALL SERVER;
```

## Защита схемы

``` sql
CREATE TRIGGER safety
ON DATABASE
FOR DROP_TABLE, ALTER_TABLE
AS
    PRINT 'You must disable Trigger "safety" to drop or alter tables!';
    ROLLBACK;
```

Для одной DDL-инструкции можно создать несколько DDL-триггеров.
DDL-триггер и вызвавшая его инструкция выполняются в одной транзакции.

------------------------------------------------------------------------

# Logon-триггеры

Logon-триггеры выполняют процедуры в ответ на событие `LOGON`.

Событие возникает при установке пользовательского сеанса с экземпляром
SQL Server.

Триггер срабатывает: 1. после проверки подлинности; 2. до фактической
установки пользовательского сеанса.

Синтаксис:

``` sql
CREATE TRIGGER trigger_name
ON ALL SERVER
{ FOR | AFTER } LOGON
AS
{ sql_statement }
```

------------------------------------------------------------------------

# Сравнение AFTER и INSTEAD OF

  Характеристика   AFTER                  INSTEAD OF
  ---------------- ---------------------- --------------------------
  Объекты          Таблицы                Таблицы и представления
  Момент           После операции         Вместо операции
  Количество       Несколько на событие   Один на событие
  Назначение       Учёт, постпроверки     Переопределение операции

## Выбор типа

**INSTEAD OF**: - проверка предусловий; - выборочное запрещение; -
изменение поведения операции.

**AFTER**: - аудит; - учёт; - проверка постусловий.

------------------------------------------------------------------------

# Когда не стоит использовать триггеры

Не следует реализовывать триггерами возможности, которые уже
обеспечиваются декларативными средствами СУБД.

Если задачу можно решить ограничением целостности или внешним ключом ---
триггер для неё не нужен.

Рекомендации из презентации: - не использовать триггер, если можно
применить `CHECK`; - не использовать `CHECK`, если можно обойтись
`UNIQUE`; - избегать сложных цепочек триггеров.

------------------------------------------------------------------------

# DML / DDL / Logon

  Тип     События                        Назначение
  ------- ------------------------------ ------------------------------------
  DML     `INSERT`, `UPDATE`, `DELETE`   Изменение данных
  DDL     `CREATE`, `ALTER`, `DROP`      Изменение структуры
  Logon   `LOGON`                        Установка пользовательского сеанса

------------------------------------------------------------------------

# Краткая шпаргалка

## Создание

``` sql
CREATE TRIGGER trigger_name
ON table_name
AFTER INSERT
AS
BEGIN
    -- код
END;
```

## INSTEAD OF

``` sql
CREATE TRIGGER trigger_name
ON table_name
INSTEAD OF INSERT
AS
BEGIN
    -- код
END;
```

## Удаление

``` sql
DROP TRIGGER trigger_name;
```

## Изменение

``` sql
ALTER TRIGGER trigger_name
...
```

## Отключение / включение

``` sql
DISABLE TRIGGER trigger_name ON object_name;
ENABLE TRIGGER trigger_name ON object_name;
```

## Специальные таблицы

``` text
INSERT  → inserted
DELETE  → deleted
UPDATE  → inserted + deleted
```

## Ошибки

``` sql
ROLLBACK;
RAISERROR(...);
```

## Главное

1.  Триггер запускается автоматически.
2.  DML работает с `INSERT`, `UPDATE`, `DELETE`.
3.  `AFTER` выполняется после операции.
4.  `INSTEAD OF` выполняется вместо операции.
5.  `inserted` содержит новые значения.
6.  `deleted` содержит старые/удалённые значения.
7.  При `UPDATE` используются обе таблицы.
8.  Триггер и вызвавшая операция находятся в одной транзакции.
9.  `ROLLBACK` отменяет изменения.
10. DDL работает с `CREATE`, `ALTER`, `DROP`.
11. Logon-триггер работает с `LOGON`.
12. Триггеры применяются для защиты, аудита, целостности и
    бизнес-правил.
13. Простые ограничения лучше реализовывать декларативными средствами
    БД.
14. Сложных цепочек и рекурсивных триггеров следует избегать.
