# Конспект — Базы данных и возможности оконных функций

## 1. Оконные функции

Оконные функции в той или иной степени поддерживаются во всех современных реляционных СУБД.

С помощью оконных функций в SQL удобно решать задачи:

- **Ранжирование** — всевозможные рейтинги.
- **Сравнение со смещением** — соседние элементы и границы.
- **Агрегация** — сумма и среднее.
- **Скользящие агрегаты** — сумма и среднее в динамике.

Это не исчерпывающий список возможностей оконных функций.

---

# 2. Ранжирование

**Ранжирование** — это построение различных рейтингов.

В примерах используется таблица `employees` с информацией о сотрудниках.

Задача: составить рейтинг сотрудников по размеру заработной платы.

Если у нескольких сотрудников одинаковая зарплата, они получают один и тот же ранг.

Например:

- Леонид и Марина имеют одинаковую зарплату → одинаковый ранг.
- Вероника и Григорий имеют одинаковую зарплату → одинаковый ранг.

---

# 3. Оконная функция

Чтобы построить рейтинг по зарплате, сначала необходимо отсортировать таблицу по убыванию зарплаты.

Затем пройти записи сверху вниз и назначить каждой записи ранг:

1. Начать с ранга `1`.
2. Если значение `salary` отличается от предыдущего значения, увеличить ранг.
3. Если значение `salary` такое же, оставить тот же ранг.

Для определения ранга достаточно анализировать значения столбца `salary`.

Эти значения называются **окном**.

---

# 4. Определение окна

В данном случае окно содержит:

1. значения столбца `salary`;
2. значения упорядочены от большего к меньшему.

В SQL описание такого окна:

```sql
WINDOW w AS (ORDER BY salary DESC)
```

Где:

- `WINDOW` — ключевое слово, показывающее, что дальше идёт определение окна;
- `w` — название окна, которое может быть любым;
- `(ORDER BY salary DESC)` — описание окна: значения `salary`, упорядоченные по убыванию.

---

# 5. DENSE_RANK()

Чтобы посчитать ранг по окну `w`, используется:

```sql
DENSE_RANK() OVER w
```

`DENSE_RANK()` — оконная функция, которая считает ранг по указанному окну.

Логика `DENSE_RANK()`:

1. Начать с `1`.
2. Увеличивать ранг каждый раз, когда очередное значение из окна отличается от предыдущего.
3. Одинаковые значения получают одинаковый ранг.
4. После одинаковых значений следующий ранг идёт без пропусков.

Пример:

```sql
SELECT
    name,
    salary,
    DENSE_RANK() OVER w AS salary_rank
FROM employees
WINDOW w AS (ORDER BY salary DESC);
```

---

# 6. Как SQL выполняет оконный запрос

Логика выполнения запроса:

1. Берётся таблица, указанная в `FROM`.
2. Из неё выбираются записи.
3. Для каждой записи рассчитывается значение `DENSE_RANK()` с помощью окна `w`.
4. Результат сортируется так, как указано в `ORDER BY`.

---

# 7. Важное свойство WINDOW

Конструкция `WINDOW` сама по себе ничего не делает с результатами запроса.

Она только **определяет окно**, которое можно использовать в запросе.

Окно начинает фактически использоваться тогда, когда в `SELECT` появляется оконная функция, которая обращается к этому окну.

Например, одно объявление:

```sql
WINDOW w AS (ORDER BY salary DESC)
```

не изменяет результат запроса без использования:

```sql
DENSE_RANK() OVER w
```

---

# 8. Оконные запросы в Oracle и MS SQL Server

В презентации отмечается, что **Oracle и MS SQL Server не поддерживают конструкцию `WINDOW`** в рассматриваемом синтаксисе.

Чтобы использовать такое оконное описание в этих СУБД, описание окна необходимо перенести непосредственно внутрь `OVER`.

Вместо:

```sql
WINDOW w AS (ORDER BY salary DESC)

SELECT
    name,
    salary,
    DENSE_RANK() OVER w
FROM employees;
```

используется:

```sql
SELECT
    name,
    salary,
    DENSE_RANK() OVER (ORDER BY salary DESC) AS salary_rank
FROM employees;
```

---

# 9. Несколько окон

Если в одном запросе необходимо использовать несколько окон, их можно перечислить через запятую в разделе `WINDOW` там, где данный синтаксис поддерживается.

Например, можно одновременно получить рейтинг сотрудников:

- по зарплате от большей к меньшей;
- по зарплате от меньшей к большей.

```sql
WINDOW
    w_desc AS (ORDER BY salary DESC),
    w_asc AS (ORDER BY salary ASC)
```

После этого окна можно использовать:

```sql
DENSE_RANK() OVER w_desc
DENSE_RANK() OVER w_asc
```

---

# 10. Секции окна

Теперь необходимо составить рейтинг сотрудников по размеру заработной платы **независимо для каждого департамента**.

Рейтинг должен начинаться заново при переходе от одного департамента к другому.

---

# 11. PARTITION BY

Сначала записи группируются по департаментам.

Внутри каждого департамента они сортируются по зарплате от большей к меньшей.

Описание такого окна:

```sql
WINDOW w AS (
    PARTITION BY department
    ORDER BY salary DESC
)
```

Здесь:

```sql
PARTITION BY department
```

указывает, как разбить окно на независимые секции.

А:

```sql
ORDER BY salary DESC
```

задаёт сортировку внутри каждой секции.

---

# 12. DENSE_RANK() с PARTITION BY

Функция расчёта ранга остаётся прежней:

```sql
DENSE_RANK()
```

Полный вариант:

```sql
SELECT
    name,
    department,
    salary,
    DENSE_RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

Результат:

- для каждого департамента рейтинг начинается с `1`;
- одинаковые зарплаты получают одинаковый ранг;
- после одинаковых зарплат ранг не пропускается.

---

# 13. Как работает секция окна

Для каждой текущей записи окно зависит от её департамента.

Внутри окна:

1. выбираются сотрудники соответствующего департамента;
2. сотрудники сортируются по `salary DESC`;
3. рассчитывается ранг;
4. при переходе к следующему департаменту ранг снова начинается с `1`.

Таким образом:

```sql
PARTITION BY department
```

отвечает за разделение данных на независимые секции.

А:

```sql
ORDER BY salary DESC
```

отвечает за порядок строк внутри каждой секции.

---

# 14. Группы с помощью оконных функций

Следующая задача — разделить сотрудников на три группы в зависимости от размера зарплаты:

- высокооплачиваемые;
- средние;
- низкооплачиваемые.

В примере используется **10 записей и 3 группы**.

Поэтому:

- две группы содержат по 3 записи;
- одна группа содержит 4 записи.

---

# 15. NTILE()

Для разделения записей на группы используется функция:

```sql
NTILE(n)
```

где `n` — количество групп.

Для трёх групп:

```sql
NTILE(3)
```

Окно:

```sql
WINDOW w AS (
    ORDER BY salary DESC
)
```

Пример:

```sql
SELECT
    name,
    salary,
    NTILE(3) OVER (
        ORDER BY salary DESC
    ) AS salary_group
FROM employees;
```

---

# 16. Как работает NTILE(n)

`NTILE(n)` разбивает все записи на `n` групп и возвращает номер группы, в которую попала каждая запись.

Например:

```text
1 — первая группа
2 — вторая группа
3 — третья группа
```

Если общее количество записей не делится на количество групп без остатка, первые группы будут крупнее последних.

Для 10 записей и 3 групп:

```text
Группа 1 → 4 записи
Группа 2 → 3 записи
Группа 3 → 3 записи
```

`NTILE()` старается разделить данные так, чтобы группы были максимально близкими по размеру.

---

# 17. Важная особенность NTILE()

`NTILE()` ориентируется на количество записей, а не на уникальность значений.

Поэтому записи с одинаковым значением зарплаты **могут попасть в разные соседние группы**.

Если граница между группами проходит внутри нескольких строк с одинаковой зарплатой, одна запись может оказаться в первой группе, а другая — во второй.

---

# 18. Функции ранжирования

Основные оконные функции ранжирования:

| Функция | Описание |
|---|---|
| `ROW_NUMBER()` | Порядковый номер строки |
| `DENSE_RANK()` | Ранг строки без пропусков |
| `RANK()` | Ранг строки с пропусками |
| `NTILE(n)` | Разбивает все строки на `n` групп и возвращает номер группы |

---

# 19. ROW_NUMBER()

`ROW_NUMBER()` нумерует строки в порядке, указанном в `ORDER BY`.

```sql
SELECT
    name,
    salary,
    ROW_NUMBER() OVER (
        ORDER BY salary DESC
    ) AS row_num
FROM employees;
```

Результат будет иметь последовательные номера:

```text
1
2
3
4
5
...
```

Даже если несколько сотрудников имеют одинаковую зарплату, `ROW_NUMBER()` присвоит им разные номера строк.

---

# 20. DENSE_RANK()

`DENSE_RANK()` присваивает одинаковый ранг строкам с одинаковым значением.

Например, если зарплаты:

```text
120
104
104
90
84
```

то ранги будут:

```text
1
2
2
3
4
```

Пропусков нет.

---

# 21. RANK()

`RANK()` похож на `DENSE_RANK()`, но после одинаковых значений **оставляет пропуск в рангах**.

Например:

```text
120
104
104
90
```

Результат `RANK()`:

```text
1
2
2
4
```

После двух строк с рангом `2` следующий ранг становится `4`.

---

# 22. Сравнение ROW_NUMBER, RANK и DENSE_RANK

Допустим, значения отсортированы так:

```text
120
104
104
90
84
```

### ROW_NUMBER()

```text
1
2
3
4
5
```

Каждая строка получает уникальный номер.

### RANK()

```text
1
2
2
4
5
```

Одинаковые значения получают одинаковый ранг, после них появляются пропуски.

### DENSE_RANK()

```text
1
2
2
3
4
```

Одинаковые значения получают одинаковый ранг, но пропусков нет.

# 24. Примеры запросов

## Рейтинг по зарплате

```sql
SELECT
    name,
    salary,
    DENSE_RANK() OVER (
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

## Рейтинг по зарплате внутри департамента

```sql
SELECT
    name,
    department,
    salary,
    DENSE_RANK() OVER (
        PARTITION BY department
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

## Разделение сотрудников на 3 группы

```sql
SELECT
    name,
    salary,
    NTILE(3) OVER (
        ORDER BY salary DESC
    ) AS salary_group
FROM employees;
```

## Нумерация строк

```sql
SELECT
    name,
    salary,
    ROW_NUMBER() OVER (
        ORDER BY salary DESC
    ) AS row_num
FROM employees;
```

## Ранг с пропусками

```sql
SELECT
    name,
    salary,
    RANK() OVER (
        ORDER BY salary DESC
    ) AS salary_rank
FROM employees;
```

WHERE фильтрует строки до группировки а еще в нем нельзя исправить агрегатные функции а в HAVING  применяется после группировки.

# 26. Шпаргалка

## Основная конструкция

```sql
ФУНКЦИЯ() OVER (
    [PARTITION BY ...]
    [ORDER BY ...]
)
```

### PARTITION BY

Разбивает строки на независимые секции.

```sql
PARTITION BY department
```

### ORDER BY

Задаёт порядок строк внутри окна.

```sql
ORDER BY salary DESC
```

### OVER

Связывает оконную функцию с определённым окном.

```sql
DENSE_RANK() OVER (...)
```

# 27. Основные функции

| Функция | Что делает |
|---|---|
| `ROW_NUMBER()` | Даёт каждой строке порядковый номер |
| `RANK()` | Одинаковые значения получают одинаковый ранг, после них возможны пропуски |
| `DENSE_RANK()` | Одинаковые значения получают одинаковый ранг без пропусков |

# 28. Главное различие функций ранжирования

Допустим, значения отсортированы так:

```text
100
90
90
80
```

| Значение | `ROW_NUMBER()` | `RANK()` | `DENSE_RANK()` |
|---:|---:|---:|---:|
| 100 | 1 | 1 | 1 |
| 90 | 2 | 2 | 2 |
| 90 | 3 | 2 | 2 |
| 80 | 4 | 4 | 3 |

**ROW_NUMBER()**

Каждая строка получает свой номер.

**RANK()**

Одинаковые значения получают одинаковый ранг, после них возможны пропуски.

**DENSE_RANK()**

Одинаковые значения получают одинаковый ранг, но пропусков нет.

---

# 29.UNION и UNION ALL

UNION объединяет результаты нескольких SELECT а  UNION ALL их просто склеивает результаты других запросов и сохраняет их.

# 30. APPLY

**APPLY** позволяет для каждой строки из левой таблицы выполнять связанный запрос к правой части.

- **CROSS APPLY** — возвращает только те строки, для которых справа найден результат.
- **OUTER APPLY** — сохраняет все строки левой таблицы, а если справа ничего нет, подставляет `NULL`.

---

# 31. VIEW и хранимая процедура

**VIEW (представление)** — сохранённый запрос, который можно использовать как виртуальную таблицу. Его удобно применять, когда нужно регулярно получать определённый набор данных, например список сотрудников вместе с названием их отдела.

**Хранимая процедура** — сохранённый набор T-SQL-команд, который можно запускать с параметрами и использовать для выполнения определённой операции. Например, процедура может получать сотрудников конкретного отдела с заданной минимальной зарплатой.

---

# 32. Оконная функция и GROUP BY

**Оконная функция** выполняет вычисление для каждой строки, сохраняя при этом отдельные строки результата. Например, `RANK()`, `AVG() OVER()` или `SUM() OVER()` позволяют получить ранг, среднее или накопительную сумму без объединения строк.

**GROUP BY** объединяет строки в группы и обычно возвращает одну строку на каждую группу. Например, `GROUP BY DepartmentID` позволяет получить среднюю зарплату отдельно по каждому отделу.

# 33. Итог

Оконные функции позволяют выполнять вычисления над набором строк, связанным с текущей строкой, не сворачивая результат в одну строку, как при обычной группировке.

В презентации рассмотрены:

- построение рейтингов;
- разбиение данных на независимые секции;
- нумерация строк;
- распределение строк по группам;
- работа с одинаковыми значениями;
- сортировка внутри окна.

Ключевые конструкции:

```sql
OVER
PARTITION BY
ORDER BY
```

Ключевые функции:

```sql
ROW_NUMBER()
RANK()
DENSE_RANK()
NTILE(n)
```

## Главное для запоминания

```text
ROW_NUMBER()  → уникальный номер каждой строки
RANK()        → одинаковый ранг + пропуски
DENSE_RANK()  → одинаковый ранг без пропусков
NTILE(n)      → распределение строк по n группам
```
