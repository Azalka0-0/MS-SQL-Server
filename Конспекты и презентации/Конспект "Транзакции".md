## 1. Модели конкурентного доступа

При одновременной работе нескольких процессов с одной базой данных
используется модель конкурентного доступа.

Основные модели:

-   **пессимистический одновременный конкурентный доступ**;
-   **оптимистический одновременный конкурентный доступ**.

### Пессимистический доступ

Предполагается, что между процессами в любое время может возникнуть
конфликт, поэтому ресурс блокируется.

### Оптимистический доступ

Предполагается, что одновременное изменение данных маловероятно.

------------------------------------------------------------------------

## 2. Транзакция

**Транзакция** --- одна или несколько команд SQL, которые либо успешно
выполняются как единое целое, либо отменяются как единое целое.

Также транзакция рассматривается как **логическая единица работы**,
обеспечивающая переход базы данных из одного согласованного состояния в
другое согласованное состояние.

### Типы транзакций

Существуют:

-   **неявные транзакции**;
-   **явные транзакции**.

### Неявные транзакции

Неявная транзакция задаёт отдельную инструкцию `INSERT`, `UPDATE` или
`DELETE` как единицу транзакции.

### Явные транзакции

Явная транзакция --- группа инструкций, начало и конец которой
обозначаются инструкциями:

``` sql
BEGIN TRANSACTION
COMMIT
ROLLBACK
```

------------------------------------------------------------------------

## 3. Свойства ACID

ACID --- четыре основных свойства транзакций:

-   **Atomicity --- Атомарность**;
-   **Consistency --- Согласованность**;
-   **Isolation --- Изолированность**;
-   **Durability --- Долговечность**.

### Atomicity --- Атомарность

Выполняются либо все изменения данных в транзакции, либо ни одно.

### Consistency --- Согласованность

Выполняемые транзакцией трансформации данных переводят базу данных из
одного согласованного состояния в другое.

### Isolation --- Изолированность

Все параллельные транзакции отделяются друг от друга.

Активная транзакция не может видеть модификации данных в параллельной
или незавершённой транзакции.

### Durability --- Долговечность

Транзакцию после фиксации нельзя отменить, кроме как другой транзакцией.

------------------------------------------------------------------------

## 4. Инструкции управления транзакциями

Основные инструкции:

``` sql
BEGIN TRANSACTION
BEGIN DISTRIBUTED TRANSACTION
COMMIT [WORK]
ROLLBACK [WORK]
SAVE TRANSACTION
SET IMPLICIT_TRANSACTIONS
```

### BEGIN TRANSACTION

`BEGIN TRANSACTION` начинает явную транзакцию.

Пример:

``` sql
BEGIN TRANSACTION;

-- SQL-инструкции

COMMIT;
```

### COMMIT

`COMMIT` фиксирует изменения, выполненные транзакцией.

После фиксации изменения становятся постоянными в рамках рассматриваемой
модели транзакций.

### ROLLBACK

`ROLLBACK` отменяет изменения текущей транзакции.

Пример:

``` sql
BEGIN TRANSACTION;

-- изменения данных

ROLLBACK;
```

### SAVE TRANSACTION

Точка сохранения определяет точку внутри транзакции, такую что все
последующие изменения данных могут быть отменены без отмены всей
транзакции.

`SAVE TRANSACTION` создаёт метку для последующей инструкции `ROLLBACK`,
имеющей такую же метку.

Пример:

``` sql
BEGIN TRANSACTION;

SAVE TRANSACTION A;

-- изменения

SAVE TRANSACTION B;

-- изменения

ROLLBACK TRANSACTION B;

-- изменения

ROLLBACK TRANSACTION A;

COMMIT TRANSACTION;
```

------------------------------------------------------------------------

## 5. Распределённые транзакции

``` sql
BEGIN DISTRIBUTED TRANSACTION
```

Запускает распределённую транзакцию.

Распределённая транзакция --- это транзакция, которая используется на
нескольких базах данных и на нескольких серверах.

Управление распределёнными транзакциями выполняется **Microsoft
Distributed Transaction Coordinator**.

Координатор --- сервер, запустивший инструкцию
`BEGIN DISTRIBUTED TRANSACTION`.

------------------------------------------------------------------------

## 6. Неявные и вложенные транзакции

### SET IMPLICIT_TRANSACTIONS ON

Включает режим неявных транзакций.

Если транзакцию явно не зафиксировать, все изменения, выполненные в ней,
откатываются при отключении пользователя.

Транзакцию могут запускать, в частности:

``` text
CREATE / ALTER / DROP / TRUNCATE TABLE
OPEN / FETCH
GRANT / REVOKE
INSERT / DELETE / UPDATE
SELECT
```

### SET IMPLICIT_TRANSACTIONS OFF

Отключает режим неявных транзакций.

### Вложенные транзакции

Явные транзакции можно вкладывать друг в друга.

Вложенные транзакции используются в хранимых процедурах, которые сами
содержат транзакции и вызываются внутри другой транзакции.

### @@TRANCOUNT

`@@TRANCOUNT` содержит число активных транзакций для текущего
пользователя.

------------------------------------------------------------------------

## 7. Журнал транзакций

**Журнал транзакций** применяется для отката или восстановления
транзакции.

Для каждой базы данных существует собственный журнал транзакций.

Database Engine сохраняет значения до и после транзакции в журнале
транзакций (`transaction log`).

### Образы записей

-   **before image** --- исходные образы записей;
-   **after image** --- преобразованные образы записей.

### LSN

**LSN (Log Sequence Number)** --- порядковый номер для каждой записи
журнала.

### Основные процессы

-   **undo** --- процесс отмены записей;
-   **redo** --- процесс повторного выполнения действий.

------------------------------------------------------------------------

## 8. Блокировки

**Блокировки** --- механизм обеспечения согласованности данных в случае
одновременного обращения к данным нескольких пользователей.

Основные свойства блокировки:

-   длительность блокировки;
-   режим блокировки;
-   гранулярность блокировки.

### Длительность блокировки

Длительность блокировки --- период времени, в течение которого ресурс
удерживает определённую блокировку.

### Режимы блокировки

Используются:

-   **разделяемая блокировка (shared lock)**;
-   **монопольная блокировка (exclusive lock)**;
-   **блокировка обновления (update lock)**.

СУБД автоматически выбирает соответствующий режим блокировки в
зависимости от типа операции --- чтения или записи.

------------------------------------------------------------------------

## 9. Разделяемая блокировка

Разделяемая блокировка резервирует ресурс только для чтения.

Особенности:

-   другие процессы не могут изменять заблокированный ресурс;
-   одновременно может существовать несколько разделяемых блокировок.

------------------------------------------------------------------------

## 10. Монопольная блокировка

Монопольная блокировка резервирует страницу или строку для монопольного
использования одной транзакции.

Применяется при:

``` text
INSERT
UPDATE
DELETE
```

Монопольную блокировку нельзя установить, если на ресурсе уже
установлена какая-либо блокировка.

------------------------------------------------------------------------

## 11. Блокировка обновления

Блокировку обновления можно устанавливать на объекты с разделяемой
блокировкой.

При этом накладывается ещё одна разделяемая блокировка.

Блокировку обновления нельзя устанавливать при наличии на объекте другой
блокировки обновления или монопольной блокировки.

При `COMMIT` транзакции блокировка обновления преобразовывается в
монопольную блокировку.

У объекта может быть только одна блокировка обновления.

------------------------------------------------------------------------

## 12. Гранулярность блокировки

Гранулярность определяет, какой объект блокируется.

Возможные уровни:

-   строки;
-   страницы;
-   индексный ключ или диапазон индексных ключей;
-   таблицы;
-   экстенты;
-   база данных.

СУБД выбирает гранулярность блокировки автоматически.

### Эскалация блокировок

Процесс преобразования большого числа блокировок уровня строки, страницы
или индекса в одну блокировку уровня таблицы называется **эскалацией
блокировок (lock escalation)**.

Настройка:

``` sql
ALTER TABLE
SET (LOCK_ESCALATION = {TABLE | AUTO | DISABLE})
```

### Lock timeout

``` sql
SET LOCK_TIMEOUT
```

Задаёт период в миллисекундах, в течение которого транзакция будет
ожидать снятия блокировки с объекта.

Значение `-1` используется по умолчанию.

### Просмотр блокировок

Для просмотра блокировок используется:

``` sql
sys.dm_tran_locks
```

------------------------------------------------------------------------

## 13. Взаимоблокировки

**Взаимоблокировка (deadlock)** --- особая проблема одновременного
конкурентного доступа, в которой две транзакции блокируют друг друга.

Типичная ситуация:

``` text
Транзакция A
    ↓
удерживает ресурс 1
    ↓
ожидает ресурс 2

Транзакция B
    ↓
удерживает ресурс 2
    ↓
ожидает ресурс 1
```

------------------------------------------------------------------------

## 14. Уровни изоляции

**Уровень изоляции** задаёт степень защищённости данных в транзакции от
возможности изменения другими транзакциями.

Основные уровни:

``` text
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
SNAPSHOT
```

### Модели

Пессимистическая модель:

``` text
READ UNCOMMITTED
REPEATABLE READ
SERIALIZABLE
```

Оптимистическая модель:

``` text
SNAPSHOT
```

Обе модели:

``` text
READ COMMITTED
```

------------------------------------------------------------------------

## 15. Проблемы конкурентного доступа

При недостаточной изоляции могут возникать следующие проблемы:

-   потеря обновлений;
-   грязное чтение;
-   неповторяемое чтение;
-   фантомное чтение.

### Потеря обновлений

Несколько транзакций одновременно могут считывать и обновлять одни и те
же данные.

Теряются все обновления данных, за исключением обновлений, выполненных
последней транзакцией.

### Грязное чтение

Происходит чтение несуществующих данных или потеря модифицированных
данных.

### Неповторяемое чтение

Один процесс считывает данные несколько раз, а другой процесс изменяет
эти данные между двумя операциями чтения первого процесса.

В результате значения двух чтений будут разными.

### Фантомное чтение

Последовательные операции чтения могут возвратить разные значения.

Может измениться число возвращаемых строк.

Возникают дополнительные фантомные строки, которые вставляются другими
транзакциями.

------------------------------------------------------------------------

## 16. READ UNCOMMITTED

`READ UNCOMMITTED` не изолирует операции чтения других транзакций.

Особенности:

-   транзакция не задаёт и не признаёт блокировок;
-   допускается грязное чтение;
-   допускается неповторяемое чтение;
-   допускается фантомное чтение.

------------------------------------------------------------------------

## 17. READ COMMITTED

`READ COMMITTED` является уровнем изоляции по умолчанию.

Транзакция выполняет проверку только на наличие монопольной блокировки
для данной строки.

Проблемы, которые могут сохраняться:

-   неповторяемое чтение;
-   фантомное чтение.

------------------------------------------------------------------------

## 18. REPEATABLE READ

`REPEATABLE READ` устанавливает разделяемые блокировки на все
считываемые данные и удерживает эти блокировки до тех пор, пока
транзакция не будет подтверждена или отменена.

При этом уровень не препятствует другим инструкциям вставлять новые
строки.

Основная проблема:

-   фантомное чтение.

------------------------------------------------------------------------

## 19. SERIALIZABLE

`SERIALIZABLE` устанавливает блокировку на всю область данных,
считываемых соответствующей транзакцией.

Предотвращает вставку новых строк другой транзакцией до тех пор, пока
первая транзакция не будет подтверждена или отменена.

Реализуется с использованием метода блокировки диапазона ключа.

Блокировка диапазона ключа блокирует элементы индексов.

------------------------------------------------------------------------

## 20. Установка уровня изоляции

Уровень изоляции задаётся инструкцией:

``` sql
SET TRANSACTION ISOLATION LEVEL
```

Доступные варианты:

``` text
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
```

------------------------------------------------------------------------

## 21. Управление версиями строк

Механизм управления оптимистическим одновременным конкурентным доступом
основан на **управлении версиями строк**.

Для всех изменений данных создаются и поддерживаются логические копии.

При каждом изменении строки СУБД сохраняет в `tempdb` исходный вид
записи.

### XSN

Каждая версия строки помечается порядковым номером транзакции:

**XSN --- transaction sequence number**.

Самая последняя версия строки сохраняется в базе данных и соединяется в
связанном списке с версией, сохранённой в `tempdb`.

### Где используется версионирование

Поддерживаются уровни изоляции:

-   `READ COMMITTED SNAPSHOT`;
-   `SNAPSHOT`.

Также механизм связан с созданием в триггерах таблиц:

``` text
inserted
deleted
```

------------------------------------------------------------------------

## 22. READ COMMITTED SNAPSHOT

`READ COMMITTED SNAPSHOT` использует управление версиями строк.

Любая другая транзакция будет читать значения, зафиксированные на момент
начала этой транзакции.

В презентации для включения приведён следующий синтаксис:

``` sql
ALTER DATABASE
SET ISOLATION LEVEL
READ COMMITTED SNAPSHOT
```

------------------------------------------------------------------------

## 23. SNAPSHOT

`SNAPSHOT` --- уровень изоляции на уровне транзакций.

Любая другая транзакция будет читать подтверждённые значения в том виде,
в каком они существовали непосредственно перед началом выполнения этой
транзакции.

На уровне базы данных включается:

``` text
ALLOW_SNAPSHOT_ISOLATION
```

Затем устанавливается уровень:

``` sql
SET TRANSACTION ISOLATION LEVEL SNAPSHOT
```

# Шпаргалка

``` text
BEGIN TRANSACTION  → начать транзакцию
COMMIT             → зафиксировать изменения
ROLLBACK           → отменить изменения
SAVE TRANSACTION   → создать точку сохранения

@@TRANCOUNT        → число активных транзакций
sys.dm_tran_locks  → просмотр блокировок

READ UNCOMMITTED   → минимальная изоляция
READ COMMITTED     → уровень по умолчанию
REPEATABLE READ    → повторяемое чтение
SERIALIZABLE       → максимальная блокировочная изоляция
SNAPSHOT           → изоляция на основе версий строк

undo               → отмена действий
redo               → повторное выполнение действий
XSN                → номер последовательности транзакции
```

## Главное

Транзакция объединяет операции с данными в единое целое и обеспечивает
переход базы данных между согласованными состояниями.

Для управления конкурентным доступом используются:

1.  блокировки;
2.  уровни изоляции;
3.  управление версиями строк.

Основная цель этих механизмов --- обеспечить согласованность данных при
одновременной работе нескольких транзакций.
